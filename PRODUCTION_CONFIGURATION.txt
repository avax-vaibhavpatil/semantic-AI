1. ENVIRONMENT VARIABLES (.env FILE)
================================================================================

Location: Create .env file in project root (or backend/ directory)

REQUIRED VARIABLES:
-------------------

# Database Configuration (REQUIRED)
DATABASE_URL=postgresql://username:password@host:5432/database_name
# Example: postgresql://prod_user:SecurePass123@db.example.com:5432/analytics_prod
# Note: Use connection pooling URL for production:
# postgresql://user:pass@host:5432/db?pool_size=20&max_overflow=40

# AI Provider Configuration (At least ONE required)
# Primary: Claude (Anthropic)
ANTHROPIC_API_KEY=sk-ant-api03-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
ANTHROPIC_MODEL=claude-3-haiku-20240307

# Secondary: Groq (Fallback)
GROQ_API_KEY=gsk_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
GROQ_MODEL=llama-3.1-8b-instant

# Optional: OpenAI (Disabled by default, can enable if needed)
# OPENAI_API_KEY=sk-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
# OPENAI_MODEL=gpt-4o-mini

OPTIONAL VARIABLES:
-------------------

# API Server Configuration
API_HOST=0.0.0.0                    # Default: 0.0.0.0 (all interfaces)
API_PORT=8000                       # Default: 8000
API_TITLE=Auto Semantic BI Platform  # Default: Auto Semantic BI Platform
API_VERSION=v1                      # Default: v1

# AI Provider Preferences
PREFERRED_AI=anthropic              # Options: "anthropic", "groq", "openai"
                                    # Default: "groq"

# Semantic Layer Configuration
SEMANTIC_JSON=backend/metadata/semantic.json
                                    # Path to semantic layer JSON file
                                    # Default: backend/metadata/semantic.json

# Database Connection Pooling
DB_POOL_SIZE=10                     # Default: 10 connections
DB_MAX_OVERFLOW=20                  # Default: 20 additional connections
DB_POOL_RECYCLE=3600                # Default: 3600 seconds (1 hour)

# Logging Configuration
LOG_LEVEL=INFO                      # Options: DEBUG, INFO, WARNING, ERROR, CRITICAL
                                    # Default: INFO
LOG_FILE=logs/app.log               # Path to log file (optional)
                                    # If not set, logs only to console
JSON_LOG_FORMAT=true                # Default: true (structured JSON logs)

# Security & Performance
DEBUG=false                         # Default: false (set to true only for dev)
CORS_ORIGINS=http://localhost:3000,https://yourdomain.com
                                    # Comma-separated list of allowed origins
                                    # Default: http://localhost:3000

# Query Limits (Security)
MAX_QUERY_ROWS=10000                # Maximum rows returned per query
                                    # Default: 10000

2. DATABASE CONFIGURATION
================================================================================

REQUIREMENTS:
-------------
- PostgreSQL 12+ (recommended: PostgreSQL 14+)
- Database user with SELECT permissions
- Connection pooling enabled

PRODUCTION SETUP:
-----------------

1. Create Production Database:
   CREATE DATABASE analytics_prod;
   CREATE USER prod_user WITH PASSWORD 'SecurePassword123!';
   GRANT CONNECT ON DATABASE analytics_prod TO prod_user;
   GRANT USAGE ON SCHEMA analytics_llm TO prod_user;
   GRANT SELECT ON ALL TABLES IN SCHEMA analytics_llm TO prod_user;

2. Create Required Schema:
   CREATE SCHEMA IF NOT EXISTS analytics_llm;

3. Create Required Tables:
   See: backend/migrations/ or database schema documentation

4. Connection Pooling:
   Use connection pooler (PgBouncer) for high-traffic deployments:
   DATABASE_URL=postgresql://user:pass@pgbouncer-host:6432/dbname

5. SSL/TLS Configuration:
   For secure connections:
   DATABASE_URL=postgresql://user:pass@host:5432/db?sslmode=require

BACKUP STRATEGY:
----------------
- Daily automated backups
- Point-in-time recovery (PITR) enabled
- Backup retention: 30 days minimum
- Test restore procedures monthly

MONITORING:
-----------
- Monitor connection pool usage
- Track query execution times
- Alert on connection failures
- Monitor database size growth

6. SECURITY CONFIGURATION
================================================================================

API SECURITY:
------------
- Enable HTTPS/TLS in production
- Use reverse proxy (Nginx, Traefik) for SSL termination
- Implement API rate limiting
- Add authentication/authorization (JWT, OAuth, etc.)

CORS CONFIGURATION:
-------------------
- Restrict CORS to specific domains
- Never use: allow_origins=["*"]
- Example: CORS_ORIGINS=https://app.yourdomain.com,https://admin.yourdomain.com

INPUT VALIDATION:
-----------------
- All user inputs validated
- SQL injection prevention (parameterized queries)
- Query result limits enforced
- Input sanitization

SECRETS MANAGEMENT:
-------------------
- Use secret management service (AWS Secrets Manager, HashiCorp Vault, etc.)
- Never hardcode secrets
- Rotate secrets regularly
- Use different secrets for dev/staging/prod

DATABASE SECURITY:
------------------
- Use read-only database user
- Enable SSL/TLS for database connections
- Restrict database access to application servers only
- Regular security audits

7. PERFORMANCE CONFIGURATION
================================================================================

DATABASE CONNECTION POOLING:
----------------------------
DB_POOL_SIZE=10                     # Base pool size
DB_MAX_OVERFLOW=20                  # Additional connections when needed
DB_POOL_RECYCLE=3600                # Recycle connections after 1 hour

TUNING GUIDELINES:
------------------
- Pool size: Start with 10, increase based on load
- Max overflow: 2x pool size is typical
- Pool recycle: Match database connection timeout
- Monitor pool usage and adjust

QUERY OPTIMIZATION:
-------------------
- Set MAX_QUERY_ROWS to prevent large result sets
- Implement query result caching where appropriate
- Monitor slow queries
- Add database indexes for frequently queried columns

ASYNC CONFIGURATION:
--------------------
- Application uses async/await for non-blocking I/O
- Database connections are async (asyncpg)
- AI API calls are async
- Monitor async task performance

RESOURCE LIMITS:
----------------
- Set appropriate memory limits
- Configure CPU limits
- Monitor resource usage
- Scale horizontally if needed

---------------------
[ ] Connection pool size configured appropriately
[ ] Query row limits enforced
[ ] Database indexes created
[ ] Slow query monitoring enabled
